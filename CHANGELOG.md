All notable changes use semantic versioning.

## 0.4.0 — 2026-09-01

- Release the Stage H.1 compressed-media preservation path. New compatible FFmpeg audiovisual ingest preserves the selected H.264 stream as bounded, versioned `EVP1` (`0x0104`) compressed packet state and compatible AAC as `EAP1` (`0x0103`) compressed packet state while keeping exact source/container or accepted HLS resources as S0. Video and audio are still decoded incrementally for fail-closed validation and resource checks, but decoded pixel/audio buffers are discarded: new compatible ingest writes no per-frame `VFR1` (`0x0101`) raw-pixel records and no new Video Profile PCM16 (`0x0102`) state. This removes the raw-frame/PCM duplication that dominated some archives; actual storage reduction remains workload-specific and no universal ratio, throughput, or latency claim is made.
- Add compressed-domain verified MP4 export for new H.1 state. Compatible EVP1 H.264 plus EAP1 AAC is remuxed without H.264 or AAC decode/re-encode. Annex-B H.264 can recover in-band SPS/PPS with FFmpeg `extract_extradata`; ADTS AAC without global decoder configuration can derive MPEG-4 AudioSpecificConfig and strip ADTS framing with `aac_adtstoasc`. Representable AAC leading trim/preroll now retains negative compressed packet timing and uses an MP4 edit list rather than failing with `encoded AAC leading trim cannot be represented by H.1 MP4 passthrough`; contradictory trim with no negative compressed-preroll evidence still fails `model_incompatible`. Irrecoverable configuration or contradictory verified state fails closed instead of silently transcoding.
- Extend explicit `codec video ingest` through the preservation-first FFmpeg bridge, including grouped multi-video ingest and bounded same-origin unencrypted HTTP/HTTPS HLS. CODEC captures the primary manifest and every accepted child resource as exact S0 before FFmpeg may consume those bytes, keeps child descriptors URL-free, and rejects encryption/key retrieval, cross-origin/private-network-denied/non-HTTP(S) children, DASH, and native FFmpeg protocol fallback outside the authorized capture boundary. Generic `codec record` remains S0-only and never automatically interprets media into EVP1/EAP1.
- Retain H.1 compatibility and dependency boundaries. `VPD1` (`0x0100`) remains the Video Profile descriptor; verified `VFR1` (`0x0101`) raw-video and Video PCM16 (`0x0102`) archives remain readable/exportable through compatibility paths; EAP1/EVP1 schemas and verified readers remain media-library independent when built with `CODEC_ENABLE_FFMPEG_VIDEO=OFF`. Default FFmpeg builds now require `libavformat`, `libavcodec`, `libavutil`, `libswscale`, and `libswresample` development modules. The retained `--layout` spelling remains accepted for ingest compatibility but does not change new EVP1 stored packet bytes.
- Remove the complete reference watermark feature from the CLI and installed C++/C surfaces, including W0 statements, W1/W2 carriers, capability fields, profile aliases, implementation, and tests. Remove generic `list streams` and `extract --stream` CLI selection while retaining generic stream C++ APIs and unchanged feed listing/extraction, with source-exact fidelity documented as the default. Preserve former archive codes 20/21 as opaque unknown record tags and former distributed error slots 10-14 as unassigned compatibility tombstones; retained numeric mappings and CODA bytes are unchanged.
- Synchronize release/package/CLI identity at 0.4.0. CMake `PROJECT_VERSION` remains the single source for library/package metadata, `codec --version`, the help banner, and the `codec capabilities` JSON version. Refresh the CLI/README description around preservation-first multi-stream capture, CODA archival, and compressed media preservation, and add `docs/releases/0.4.0.md` with migration, storage, compatibility, HLS, packet-remux, AAC-preroll, failure-mode, and release-verification guidance.
