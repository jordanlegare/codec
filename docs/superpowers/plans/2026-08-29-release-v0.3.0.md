# CODEC v0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut CODEC v0.3.0 from the current F.7-complete `main`, publishing all changes accumulated since v0.2.0 with internally consistent package, README, CLI, and changelog version metadata.

**Architecture:** Use the repository's existing guarded `.github/workflows/release.yml` contract. Prepare release metadata on `automation/release-v0.3.0`, prove the CLI reports the CMake project version rather than a stale literal, merge only an exact-green head to `main`, then create `release/v0.3.0` at that exact merged `main` commit so GitHub Actions creates tag `v0.3.0` and release `CODEC v0.3.0`.

**Tech Stack:** CMake 3.20+, C++20, Bash/CTest, GitHub Actions.

**Spec:** `.github/workflows/release.yml` (guarded release contract) and the established v0.2.0 release convention in `CHANGELOG.md` / PR #29.

## Global Constraints

- Release version is exactly `0.3.0`; Git tag is exactly `v0.3.0`.
- Release date is `2026-08-29`.
- Release scope is the current F.7-complete tree; do not add F.8 functionality.
- Preserve S0/S1/D, CODA, Stage E, Stage F.1-F.7, C ABI, and distributed wire semantics unchanged.
- `release/v0.3.0` must point exactly at current `main` when the Release workflow runs.
- The release workflow must remain unchanged unless a demonstrated release blocker requires a fix.
- No performance, deployment, network transport, CLI-distributed-execution, or v1.0 readiness claim is added.

### Task 1: Prove and repair CLI version synchronization

**Files:**
- Modify: `tests/cli_integration.sh`
- Modify: `CMakeLists.txt`
- Modify: `src/cli/main.cpp`

**Interfaces:**
- Consumes: CMake `${PROJECT_VERSION}` and the existing `codec capabilities` JSON output.
- Produces: the CLI usage banner and `capabilities.version` from a CMake-provided `CODEC_VERSION_STRING`, with the integration test receiving the configured expected version as its second argument.

- [ ] **Step 1: Write the failing integration assertion**

Change the test invocation to pass `${PROJECT_VERSION}`:

```cmake
add_test(NAME codec-cli-integration
  COMMAND bash ${CMAKE_CURRENT_SOURCE_DIR}/tests/cli_integration.sh
               $<TARGET_FILE:codec_cli> ${PROJECT_VERSION})
```

At the top of `tests/cli_integration.sh`, require the second argument and assert the real CLI output:

```bash
expected_version=${2:?expected CODEC version required}
"$codec_bin" capabilities > "$test_dir/capabilities.json"
grep -Fq "\"version\":\"$expected_version\"" "$test_dir/capabilities.json"
```

- [ ] **Step 2: Run CI to verify RED**

Expected: configure/build succeeds; `codec-cli-integration` fails because the executable currently reports hard-coded `0.1.0` while CMake reports `0.2.0`.

- [ ] **Step 3: Inject the configured project version into the CLI**

Add to the `codec_cli` target:

```cmake
target_compile_definitions(codec_cli PRIVATE
  CODEC_VERSION_STRING="${PROJECT_VERSION}")
```

Replace the two hard-coded CLI version literals in `src/cli/main.cpp` with `CODEC_VERSION_STRING`:

```cpp
<< "CODEC " CODEC_VERSION_STRING " - preservation-first audio feed archive and identity\n\n"
```

and

```cpp
std::cout << "{\"version\":\"" CODEC_VERSION_STRING "\",";
```

- [ ] **Step 4: Run the full CI matrix**

Expected: GCC, Clang, full CTest including `codec-cli-integration`, install/package consumer, and sanitizers pass.
